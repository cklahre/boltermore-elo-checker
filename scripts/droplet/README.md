# Discord bot on a DigitalOcean droplet

Layout on the server:

| Path | Purpose |
|------|---------|
| `/opt/eloevent/repo/` | Mirror from GitHub Actions — includes **`bcp-matches.manifest`** + shard JSON if you commit them; **`refresh-leaderboard.sh`** and **`start-eloevent-discord-bot.sh`** fall back here when **`/opt/eloevent/data/`** has no matches |
| `/opt/eloevent/bin/eloevent-bot` | Discord bot binary (deployed by CI) |
| `/opt/eloevent/bin/local-elo` | Rebuild `leaderboard.json` from matches (deployed by CI) |
| `/opt/eloevent/bin/bcp-harvest-events` | Weekly BCP event discovery (deployed by CI) |
| `/opt/eloevent/bin/bcp-export-matches` | Weekly pairing export (deployed by CI) |
| `/opt/eloevent/bin/bcp-matches-manifest` | Regenerates shard manifest after each pull (deployed by CI) |
| `/opt/eloevent/data/bcp-matches.json` | Fallback for `refresh-leaderboard` **only**: when no manifest anywhere (**Discord bot launcher does not use repo monoliths**) |
| `/opt/eloevent/data/bcp-matches.manifest` | Preferred match pool — weekly pull writes here (seeds from **`repo/`** on first run) |
| `/opt/eloevent/data/bcp-matches-YYYY-MM-DD.json` | Dated shards; weekly job appends a new one each Monday |
| `/opt/eloevent/data/leaderboard.json` | Generated by `refresh-leaderboard.sh` |
| `/opt/eloevent/env/bot.env` | `DISCORD_BOT_TOKEN`, `DISCORD_GUILD_ID`; optional **`ELO_MATCHES_MANIFEST`** / **`ELO_MATCHES_JSON`** |
| `/opt/eloevent/scripts/start-eloevent-discord-bot.sh` | **ExecStart launcher** — **`data/`** first, **`repo/`** fallback |
| `/opt/eloevent/env/refresh.env` | **`PULL_MATCHES=1`** (default) + optional `SINCE=` / throttle knobs |
| `/opt/eloevent/scripts/pull-matches.sh` | Harvest since newest shard → export dated shard → rewrite manifest |
| `/opt/eloevent/scripts/refresh-leaderboard.sh` | Optional pull, then `local-elo` + restart Discord bot |
| systemd **`eloevent-refresh-leaderboard.timer`** | **Monday 20:00 UTC** (~4pm EDT / 3pm EST); install/enable via `install-on-droplet.sh` or CI deploy |

## Weekly automation (Monday afternoon)

Each Monday the timer runs with **`PULL_MATCHES=1`**:

1. **`pull-matches.sh`** finds the newest `bcp-matches-YYYY-MM-DD.json` under **`data/`**, uses **day-after** as `-since` (or **`SINCE=`** from `refresh.env`).
2. Harvests **GT-scale** BCP events only (default **`MIN_PLAYERS=30`**, **`MIN_ROUNDS=5`**, **`MAX_SPAN_DAYS=7`**, **`EXCLUDE_NAME=league,season,ladder,rtt`**), exports pairings to **`bcp-matches-<today>.json`**, regenerates **`bcp-matches.manifest`**.
3. Rebuilds **`leaderboard.json`** and restarts the Discord bot.

First weekly run seeds **`data/`** from **`repo/`** if **`data/`** has no manifest yet (so you can keep historical shards in git or sync them once with `sync-matches-to-droplet.sh`).

Manual run now:

```bash
PULL_MATCHES=1 /opt/eloevent/scripts/refresh-leaderboard.sh
# leaderboard only (skip BCP pull):
PULL_MATCHES=0 /opt/eloevent/scripts/refresh-leaderboard.sh
```

Check schedule: `systemctl list-timers eloevent-refresh-leaderboard.timer`

## One-time droplet setup

1. Install Go is **not** required on the droplet if you only use CI-built binaries.
2. Clone this repo (or copy `scripts/droplet/` onto the box) and run:

   ```bash
   sudo bash scripts/droplet/install-on-droplet.sh
   ```

3. If you are **not** using CI to write Discord env yet, edit `/opt/eloevent/env/bot.env` and `chmod 600` it (deploy overwrites this file when `DISCORD_*` secrets are set).
4. Seed match shards into **`/opt/eloevent/data/`** (recommended) via **`sync-matches-to-droplet.sh`**, **or** commit shards so CI fills **`/opt/eloevent/repo/`** — the first weekly pull copies repo shards into **`data/`**.
5. Optional overrides: **`ELO_MATCHES_MANIFEST`** / **`ELO_MATCHES_JSON`** in `bot.env`; **`SINCE=`** / sleep knobs in **`refresh.env`**.
6. Run `PULL_MATCHES=1 /opt/eloevent/scripts/refresh-leaderboard.sh` once (or wait for Monday), then `systemctl start eloevent-discord-bot`.

## GitHub Actions

Required repository **secrets** (names wired in the workflows):

| Secret | Role |
|--------|------|
| `SSH_KEY` | SSH private key for the droplet (full PEM/OpenSSH block, including newlines). |
| `DO_HOST` | Droplet hostname or IP (`ssh-keyscan`, `scp`/`ssh` target). |
| `DISCORD_BOT_TOKEN` | Discord bot token; written into `/opt/eloevent/env/bot.env` on each deploy. |
| `DISCORD_GUILD_ID` | Guild snowflake for slash registration; same file as above. |

Optional repository **variable** `DO_SSH_USER`: SSH username (defaults to **`root`** if unset).

Nothing else is required for the two workflows—no personal access token, PAT, or `GITHUB_TOKEN` access beyond checkout.

- **Deploy on push to `main`**: `.github/workflows/deploy-discord-droplet.yml` builds Linux `amd64` binaries (bot, `local-elo`, harvest/export/manifest), **`rsync`s the checkout to `/opt/eloevent/repo/`**, installs systemd units for **`eloevent-discord-bot`** and **`eloevent-refresh-leaderboard.timer`** (weekly Monday pull+refresh), and restarts the Discord bot. Pushes that only touch `site/**` are ignored.

Repo sync excludes: `.git/`, `.github/`, `.cursor/`, **`bcp-matches.json`**, and build artifacts (`eloevent-bot`, `local-elo`, `bcp-*`). The sync uses **`--delete`**, so anything you add only under **`/opt/eloevent/repo/`** and not in git will be removed on the next deploy. **`/opt/eloevent/data/`** is never deleted by deploy.

- **Manual leaderboard refresh (GitHub Actions)**: `.github/workflows/refresh-leaderboard-droplet.yml` is **`workflow_dispatch` only** — SSH-runs **`refresh-leaderboard.sh`** (honors **`PULL_MATCHES`** in `refresh.env`). Routine automation is **`eloevent-refresh-leaderboard.timer`** on the droplet.

Both workflows SSH in and expect `/opt/eloevent` dirs to exist (`install-on-droplet.sh` creates them).

## Match exports: single file vs shards

For large histories it is convenient to **archive** dated pulls (e.g. `bcp-matches-2026-05-03.json`), export **only newer events** into a smaller `bcp-matches-new.json`, list both in **`bcp-matches.manifest`** (paths relative to the manifest file are fine), then run:

```bash
go run ./cmd/local-elo -matches-manifest bcp-matches.manifest -out-json leaderboard.json
# or concatenate into one artifact:
go run ./cmd/bcp-merge-matches -out bcp-combined.json bcp-archive.json bcp-new.json
# or generate a manifest from dated shards in the current directory:
go run ./cmd/bcp-matches-manifest -out bcp-matches.manifest -sort name
```

`local-elo`, **`player-history`**, and **`eloevent-discord-bot`** merge shards with **`DedupeMatchRows`** (pairing-first). Prefer **disjoint** shards; overlaps keep the **first** occurrence — list **oldest batches first**.

## Manifest + shards (preferred)

Do **not** commit gigabyte exports without need; **dated shards** + **`bcp-matches.manifest`** are the normal workflow.

1. **Copy shards from your laptop, rebuild leaderboard on the droplet** — by default uploads repo-root **`bcp-matches.manifest`** and each listed **`bcp-matches-YYYY-MM-DD.json`**:  
   `SSH_IDENTITY=~/.ssh/id_do_personal DO_HOST=YOUR_DROPLET ./scripts/droplet/sync-matches-to-droplet.sh`  
   Override manifest path with **`MATCHES_MANIFEST=/path/to/x.manifest`** if needed.

2. Emergency **legacy monolith** (`bcp-matches.json` onto `data/`) only when you deliberately set **`SYNC_MONOLITH=1`** and **`MATCHES_JSON`** on the sync script (drops **`data/bcp-matches.manifest`**).

3. **Manual only**: rsync manifest + shards to **`/opt/eloevent/data/`**, then **`/opt/eloevent/scripts/refresh-leaderboard.sh`**.

4. Committing shards under **`/`** lets CI **`rsync`** them to **`/opt/eloevent/repo/`** — weekly pull seeds **`data/`** from that mirror on first run.

5. **Weekly on the droplet** (preferred): timer + **`pull-matches.sh`** appends a new dated shard under **`data/`** every Monday; no laptop sync required after the initial seed.

6. **GitHub Actions** refresh runs **`refresh-leaderboard.sh`** over SSH; prefer keeping large shards in **`data/`** (outside the repo rsync) if files are enormous.
