# Discord bot on a DigitalOcean droplet

Layout on the server:

| Path | Purpose |
|------|---------|
| `/opt/eloevent/repo/` | Mirror from GitHub Actions — includes **`bcp-matches.manifest`** + shard JSON if you commit them; **`refresh-leaderboard.sh`** and **`start-eloevent-discord-bot.sh`** fall back here when **`/opt/eloevent/data/`** has no matches |
| `/opt/eloevent/bin/eloevent-bot` | Discord bot binary (deployed by CI) |
| `/opt/eloevent/bin/local-elo` | Rebuild `leaderboard.json` from matches (deployed by CI) |
| `/opt/eloevent/data/bcp-matches.json` | Legacy single-file match export (**not** in git) |
| `/opt/eloevent/data/bcp-matches.manifest` | Optional — if present, **wins over** shards only in **`repo/`** ( **`refresh`** + **`start-eloevent-discord-bot`** precedence) |
| `/opt/eloevent/data/leaderboard.json` | Generated by `refresh-leaderboard.sh` |
| `/opt/eloevent/env/bot.env` | `DISCORD_BOT_TOKEN`, `DISCORD_GUILD_ID`; optional **`ELO_MATCHES_MANIFEST`** / **`ELO_MATCHES_JSON`** to pin pools (launcher honors these) |
| `/opt/eloevent/scripts/start-eloevent-discord-bot.sh` | **ExecStart launcher** — same match resolution as **`refresh-leaderboard.sh`** (**`data/`** first, **`repo/`** fallback) |
| `/opt/eloevent/env/refresh.env` | Optional: `UPDATE_MATCHES_CMD` to fetch new matches before Elo run |
| `/opt/eloevent/scripts/refresh-leaderboard.sh` | Regenerates leaderboard + restarts Discord bot (`local-elo`) |
| systemd **`eloevent-refresh-leaderboard.timer`** | Runs that script daily (~**06:00** server-local time — often UTC); install/enable via `install-on-droplet.sh` or CI deploy |

## One-time droplet setup

1. Install Go is **not** required on the droplet if you only use CI-built binaries.
2. Clone this repo (or copy `scripts/droplet/` onto the box) and run:

   ```bash
   sudo bash scripts/droplet/install-on-droplet.sh
   ```

3. If you are **not** using CI to write Discord env yet, edit `/opt/eloevent/env/bot.env` and `chmod 600` it (deploy overwrites this file when `DISCORD_*` secrets are set).
4. Match data lives in **`/opt/eloevent/data/`** *or*, if committed in **`main`**, under **`/opt/eloevent/repo/`** after the next deploy (**`refresh-leaderboard.sh`** prefers **`data/`** manifest/JSON then **`repo/`**). Putting matches only under **`repo/`** is enough for manifests + shards in git — no manual copy into **`data/`** required.
5. Optional overrides: **`ELO_MATCHES_MANIFEST`** / **`ELO_MATCHES_JSON`** in `bot.env` pin inputs (launcher delegates to **`eloevent-bot`** env flags — don’t duplicate the pool).
6. Run `/opt/eloevent/scripts/refresh-leaderboard.sh` once, then `systemctl start eloevent-discord-bot` (or rely on CI after pushing to `main`).

## GitHub Actions

Required repository **secrets** (names wired in the workflows):

| Secret | Role |
|--------|------|
| `SSH_KEY` | SSH private key for the droplet (full PEM/OpenSSH block, including newlines). |
| `DO_HOST` | Droplet hostname or IP (`ssh-keyscan`, `scp`/`ssh` target). |
| `DISCORD_BOT_TOKEN` | Discord bot token; written into `/opt/eloevent/env/bot.env` on each deploy. |
| `DISCORD_GUILD_ID` | Guild snowflake for slash registration; same file as above. |

Optional repository **variable** `DO_SSH_USER`: SSH username (defaults to **`root`** if unset).

Nothing else is required for the two workflows—no personal access token, PAT, or `GITHUB_TOKEN` access beyond checkout.

- **Deploy on push to `main`**: `.github/workflows/deploy-discord-droplet.yml` builds Linux `amd64` binaries, **`rsync`s the checkout to `/opt/eloevent/repo/`** (same excludes as below), rsyncs binaries plus scripts, installs systemd units for **`eloevent-discord-bot`** and **`eloevent-refresh-leaderboard.timer`** (daily refresh — enable starts on first deploy), and restarts the Discord bot. Pushes that only touch `site/**` are ignored.

Repo sync excludes: `.git/`, `.github/`, `.cursor/`, **`bcp-matches.json`** (keep only on-disk under `/opt/eloevent/data/`), and the ephemeral **`eloevent-bot`** / **`local-elo`** build artifacts (those land under **`bin/`** instead). The sync uses **`--delete`**, so anything you add only under **`/opt/eloevent/repo/`** and not in git will be removed on the next deploy.

- **Manual leaderboard refresh (GitHub Actions)**: `.github/workflows/refresh-leaderboard-droplet.yml` is **`workflow_dispatch` only** — use the Actions tab to trigger an SSH run of **`refresh-leaderboard.sh`** when you want a refresh immediately without opening a terminal. Routine automation is handled by **`eloevent-refresh-leaderboard.timer`** on the droplet (enabled on deploy).

Both workflows SSH in and expect `/opt/eloevent` dirs to exist (`install-on-droplet.sh` creates them).

## Match exports: single file vs shards

For large histories it is convenient to **archive** dated pulls (e.g. `bcp-matches-2026-05-03.json`), export **only newer events** into a smaller `bcp-matches-new.json`, list both in **`bcp-matches.manifest`** (paths relative to the manifest file are fine), then run:

```bash
go run ./cmd/local-elo -matches-manifest bcp-matches.manifest -out-json leaderboard.json
# or concatenate into one artifact:
go run ./cmd/bcp-merge-matches -out bcp-combined.json bcp-archive.json bcp-new.json
# or generate a manifest from dated shards in the current directory:
go run ./cmd/bcp-matches-manifest -out bcp-matches.manifest -sort name
```

`local-elo`, **`player-history`**, and **`eloevent-discord-bot`** merge shards with **`DedupeMatchRows`** (pairing-first). Prefer **disjoint** shards; overlaps keep the **first** occurrence — list **oldest batches first**.

## Large `bcp-matches.json` / manifests

Do **not** commit gigabyte exports.

1. **Copy from your laptop, rebuild leaderboard on the droplet** — SSH runs **`/opt/eloevent/scripts/refresh-leaderboard.sh`** so manifest vs single-file matches what you use on the server:  
   - Single JSON:  
     `SSH_IDENTITY=~/.ssh/id_do_personal DO_HOST=YOUR_DROPLET ./scripts/droplet/sync-matches-to-droplet.sh`  
     (Uses `bcp-matches.json` at repo root by default; **`MATCHES_JSON=...`** to override.) This path **removes a stale `/opt/eloevent/data/bcp-matches.manifest`** so the uploaded monolith wins.  
   - Shards:  
     `MATCHES_MANIFEST=./path/to/bcp-matches.manifest DO_HOST=YOUR_DROPLET ./scripts/droplet/sync-matches-to-droplet.sh`  
     Uploads **`bcp-matches.manifest`** to the fixed droplet path and **`rsync`s every shard listed** there (comments and blank lines skipped; paths resolve relative to the manifest file’s directory on your machine). Omit `SSH_IDENTITY` when your `ssh` config already picks the right key.)
2. **Manual only**  

   Single file:  

   `rsync -avP ./bcp-matches.json root@YOUR_DROPLET:/opt/eloevent/data/`  

   Then on the droplet: `/opt/eloevent/bin/local-elo -matches /opt/eloevent/data/bcp-matches.json -out-json /opt/eloevent/data/leaderboard.json` and `systemctl restart eloevent-discord-bot`.

   Multiple shards + manifest: rsync dated JSON shards and `bcp-matches.manifest` to `/opt/eloevent/data/` (see `scripts/droplet/bcp-matches.manifest.example`), then `./scripts/droplet/refresh-leaderboard.sh` prefers the manifest when present.
3. **Automate pull on the droplet** (later): set `UPDATE_MATCHES_CMD` in `/opt/eloevent/env/refresh.env` to `curl`/`wget` from a private URL (e.g. DigitalOcean Spaces with a scoped token), or run your existing export script after checking out tooling on the droplet.
4. **GitHub Actions** should only run `refresh-leaderboard.sh` over SSH; do not upload gigabytes through Actions unless you add a deliberate artifact step.

The systemd timer triggers `refresh-leaderboard.sh` **on** the droplet against match files already there (manifest-first); add **`UPDATE_MATCHES_CMD`** in `refresh.env` to pull rebuilds (`curl`/export) so the pool updates without syncing from your laptop.
